# 1プレイヤー通しテスト手順

## 1. 目的

添付ZIPを使用し、人間1人・AI7人のランダムな8人村を作成して、勝敗公開後の全参加者の感想登録を経て`ended`になるまで、または人間の`【ストップ】`まで1ゲームを継続してください。

- AIターン: 本番`promptText`をAIが読み、生成した`rawResponse`を本番パーサー・バリデーター・状態遷移へ通す。
- 人間ターン: 本人が知る秘密情報と全公開会話を提示し、返答を改変せず本番の人間操作経路へ登録する。

定型応答、代理入力、対象名の機械置換、筋書きによる進行は禁止します。

---

## 2. 実行方式

ブラウザ、GUI、外部AI API、複数エージェント、追加パッケージは必須ではありません。次の順で実施してください。

1. 正規ビルドした配布アプリ
2. 最新の本番ES Modulesを補助スクリプトから直接実行
3. 作業用コピーに限り、import解決、ローダー設定、最小限のDOMスタブを使用

2または3は「ソースレベル通しテスト」と記録し、Electronで生成された配布アプリを確認したとは扱わないでください。

現行構成では、正規配布アプリは`配布版を作成.cmd`または`tools`配下の`npm run release`が`output/dist/`へ生成するWindows x64版ZIP／Setup EXEです。通常のWebブラウザへ`index.html`を直接開く方式ではありません。

ソースレベル試験で使用する正本は次です。

- 本番ES Modules: `app/renderer/js/`
- Renderer入口: `app/renderer/js/app/bootstrap.js`
- 配布bundle: `app/renderer/generated/bundle.js`
- Build ID: `app/renderer/generated/buildInfo.js`（`BUILD_ID`と`BUNDLE_SHA256`）
- Electron Main・保存・API通信: `app/main/`
- ゲーム回帰: `tools/tests/game/`
- デスクトップ回帰: `tools/tests/desktop/`

外部AI APIがない場合は、このスレッドのAIが各`promptText`を一件ずつ読み、対象キャラクターとして回答してください。

```text
AI: 本番promptText → AI rawResponse → 本番解析 → 本番検証 → 本番状態遷移
人間: 本番入力待ち → 入力画面提示 → 人間の返答 → 本番人間操作検証 → 本番状態遷移
```

各AI用`promptText`は新しい独立入力としてAIへ渡してください。前ターンのプロンプト、回答、人間の秘密情報、完全状態、テスト側の推理や正解情報を同じ入力コンテキストへ残してはいけません。再試行も、元の`promptText`と今回の検証エラーだけを渡す新しい独立入力として実行してください。

## 3. 開始前確認

### 完全ソースの判定

現行の完全ソースには、最低限次が必要です。

```text
AI人狼を起動.cmd
配布版を作成.cmd
ソース一式作成.cmd
README.md
app/README.txt
app/package.json
app/main/
app/renderer/
tools/package.json
tools/package-lock.json
tools/build/
tools/tests/
docs/
```

`ソース一式作成.cmd`が生成する`output/ai_werewolf_manager_vXX_XX_XX.zip`（製品版1.0.0では`output/ai_werewolf_manager_v01_00_00.zip`）は、`.github/`、`output/`、`tools/node_modules/`を意図的に除外します。この3領域がないことだけで差分ZIPまたは不完全ソースと判定してはいけません。反対に、`app/`、`tools/build/`、`tools/tests/`、`docs/`のいずれかが欠ける場合は完全ソースとして扱いません。

### 現行の検査・起動方法

Windowsで配布アプリを製造する場合は、プロジェクト直下の`配布版を作成.cmd`を使用します。成果物は`output/dist/`へ生成されます。ソース版をGUIで確認する場合は`AI人狼を起動.cmd`を使用します。

ソースだけを検査する場合は作業用コピーで次を実行します。

```text
cd tools
npm ci
npm run verify
```

`npm run verify`は、製造事前ゲート、決定的bundle生成、生成後の完全製造ゲート、ゲーム回帰、デスクトップ回帰の順で実行します。bundle生成により`app/renderer/generated/buildInfo.js`、`app/renderer/generated/bundle.js`、`app/renderer/index.html`のbundleキャッシュキーが更新されるため、元ZIPを不変のまま監査する場合は必ず作業用コピーで実施してください。

1. ZIPを展開し、次の正本からVersion、Schema、Prompt Spec、Build IDを確認する。
   - Version: `app/package.json`と`app/renderer/js/config/constants.js`
   - Schema／Prompt Spec: `app/renderer/js/config/constants.js`
   - Build ID: `app/renderer/generated/buildInfo.js`（`BUILD_ID`と`BUNDLE_SHA256`）
2. HTML、CSS、JavaScript、設定、データ、手順書が揃っているか確認する。
3. 差分ZIPしかなく完全なベース一式がない場合は中止する。
4. 利用可能な範囲で既存テストと正規ビルドを実行する。
5. Build ID・BUNDLE_SHA256・現行ソース・同梱bundleの整合を確認する。
6. 不整合または正規ビルド不可なら、配布アプリ試験を未合格とし、ソースレベル試験へ切り替える。

`tools/node_modules`、`output`、`.github`、Webブラウザ、一般公開パッケージがないことだけで差分ZIPと判定してはいけません。

ZIP内の本番ソースは変更禁止です。作業用コピーの環境適合調整は認めますが、本番ロジック、プロンプト、解析、検証、状態遷移、人間操作処理を変更・迂回してはいけません。

## 4. ゲーム設定

- 標準人狼、8人
- 人間1人・AI7人
- キャラクター重複なし
- キャラクター、人間操作対象、配役対応はランダム
- 標準8人配役は村人×2、占い師、霊能者、狩人、狂人、人狼×2
- 昼発言は1人3回、順番制、質問への回答優先あり。通常は3巡完了で昼議論完了とする。3巡目のCO後、そのCO時点で発言回数を使い切っていた生存者（CO者を除く）がいる場合だけ、対象者へCO再検討発言を1回ずつ追加する
- 初夜の人狼会話あり、初夜襲撃なし
- 初日占いは対象選択、初夜護衛なし
- 自己投票なし、棄権なし
- 投票中は非公開、確定後に全投票先を公開
- 決選投票上限は1回。上限後の同票はランダム処刑
- 処刑時の役職は非公開
- 人狼共有会話は人狼だけが参加し、各夜1人1回。襲撃がある夜は各生存人狼が秘密投票し、最多票の対象を襲撃する。最多同率は同率候補からランダム決定する
- その他は`app/renderer/js/config/constants.js`の`DEFAULT_RULES`に一致させる

乱数結果を変更してはいけません。シードを保存できない場合は、キャラクター、配役、人間操作対象、発言順、初期設定をマニフェストへ保存してください。

---

## 5. 対話の継続

開始確認は求めず、次の人間入力待ちまでAI操作と状態遷移を連続実行してください。

人間入力待ちに到達した場合だけ入力を求め、有効な返答を登録後、直ちに同じゲームを再開してください。続行確認、別ゲーム開始、状態初期化、進行地点の飛ばしは禁止します。

入力が完全一致で`【ストップ】`の場合だけ強制中断します。

- `ストップ`、`停止`、`やめる`などは中断にしない
- 無効入力はエラーを示して同じ入力待ちを継続する
- `【ストップ】`後はAI応答、投票、夜行動、状態遷移を実行しない
- 中断時点の状態と監査データを保存し、勝者を作らない

## 6. 人間入力

### 入力を求める場面

次の場合だけ人間へ入力を求めてください。

- 初期役職・本人限定結果の確認
- 昼の通常公開発言
- 個人質問への回答優先発言
- 通常投票・決選投票
- 占い・護衛対象
- 人狼共有発言
- 襲撃先の秘密投票
- 勝敗公開後の公開感想

AIターン、GM公開処理、集計、処刑、夜明け、勝敗確認では入力を求めません。

### 提示内容

毎回、次を一つの入力画面として提示してください。

```text
## 人間プレイヤー入力

### 現在の状況
Day / フェーズ / 入力種別 / 名前 / 生存状態 / 残り発言回数

### あなたの秘密情報
真の役職 / 陣営 / 個別情報 / 既知の人狼仲間
本人限定の能力結果 / 自分の投票・夜行動
人狼共有会話・共有作戦 / 暫定襲撃先・了承状況

### 公開会話履歴
#イベント番号 Day N 発言者: 公開発言

### その他の公開情報
公開CO / 公開能力結果 / 投票結果 / 処刑結果 / 夜明け結果

### 今回入力できる内容
候補 / 入力形式 / 注意事項
```

該当しない項目は省略できます。本人がその時点で知る情報だけを提示し、他者の真役職、内部メモ、未公開情報、将来情報、GM完全状態を表示してはいけません。

公開会話履歴には、その時点までの全公開発言をイベント番号・Day付きで時系列表示してください。直前に登録されたAI発言も含め、要約へ置き換えません。発言がなければ「公開発言なし」と記載します。

入力画面の提示後は、返答までゲームを進めてはいけません。AI用`promptText`、心の声、判断更新、内部メモも表示禁止です。

### 入力形式

#### 通知確認

```text
【確認】
```

`【確認】`まで通知済みにせず、`【ストップ】`以外の入力には形式を再提示します。

#### 昼の公開発言

```text
【公開発言】
公開する本文

【個人質問先】指定なし / 対象名

【CO操作】
action: none / declare / change / withdraw
roleId: 現在の配役に存在するCO可能役職
```

発言しない場合は`【パス】`、今回だけ後回しにする場合は`【後回し】`です。

本文は変更せず登録し、COと個人質問先は構造化指定だけを使用します。自然文からCO・質問先を推測せず、公開発言本文との意味的一致も検査しません。質問先が次の通常発言者なら、その発言内へ回答を統合します。それ以外は直後に回答優先フェーズを挿入します。

現行の人間通常発言経路`recordHumanSpeech`が受け付ける構造化項目は`playerId`、`content`、`coOperation`、`questionTargetId`です。通常発言からAI用`abilityClaims`、判断状態、心の声、内部メモを生成または登録してはいけません。人間が能力結果を通常発言本文で述べた場合は本文をそのまま公開しますが、構造化された公開能力結果として補完せず、この制約を評価書へ記録してください。

#### 個人質問への回答優先発言

```text
【質問への回答】
公開する回答本文

【CO操作】
action: none / declare / change / withdraw
roleId: 現在の配役に存在するCO可能役職

【能力結果公開】
action: none / add
必要時だけ、役職・観測Day・対象・結果・選択根拠・公開根拠イベントを指定
```

`recordHumanPriorityAnswer`へ`playerId`、システムが固定した`questionEventId`、`content`、任意`coOperation`、任意`abilityClaims`だけを渡します。回答優先発言は通常発言回数・巡・発言順を消費せず、新しい質問先を指定できません。回答本文の内容妥当性は検査しません。

#### 投票・夜行動

```text
【投票】対象名
【対象】対象名
```

現在有効な候補だけを提示してください。投票確定まで他者の投票を表示せず、決選投票では決選候補だけを提示します。占い・護衛には理由を追加せず、結果は解決後の本人限定通知で提示します。

#### 人狼共有・襲撃先投票

```text
【人狼共有発言】
仲間へ共有する本文

【共有発言なし】

【襲撃投票】対象名
```

人狼にだけ現在の共有会話と共有作戦を提示し、共有発言を変更せず登録してください。襲撃先は生存人狼ごとの秘密投票として登録し、全票確定まで他の人狼の投票先を表示しません。最多票を襲撃し、最多同率だけ同率候補からランダム決定します。

#### 勝敗後の公開感想

```text
【公開感想】
1～2文の短い感想
```

勝敗と公開結果を確認した後、全参加者について順番に登録します。人間の本文は変更せず`recordResultImpression`へ渡し、全員分が完了してから`ended`へ進みます。

### 無効入力

人間の入力を補完、改善、要約、代筆してはいけません。無効な場合は、入力画面、入力本文、エラー、再入力説明を保存し、有効な入力または`【ストップ】`まで同じ入力待ちを継続してください。

## 7. AIターン

各AIターンを一件ずつ次の順で処理してください。

1. 現在状態から本番`promptText`を生成する。
2. AIはその内容だけを読み、対象キャラクターとして`rawResponse`を新規生成する。
3. `rawResponse`を変更せず本番パーサーへ渡す。
4. 本番バリデーターへ渡す。
5. 成功時だけ本番ゲーム状態へ登録する。
6. 状態更新後に次のターンを生成する。
7. 次が人間入力ならAI回答を作らず、第6節の入力画面を提示する。

後続ターンの先行生成、複数ターンの一括生成、人間用AI回答の生成は禁止します。

AI判断に使ってよいのは、そのターンの`promptText`だけです。他者の真役職、内部メモ、人間の秘密情報、未公開能力結果・投票、将来情報、完全状態の正解筋を混入させてはいけません。

禁止する生成方法:

- 名前、日付、候補、役職だけを置換するテンプレート
- ランダム選択だけで発言・投票・能力対象を決める処理
- 全AIへ同じ文型を使用する処理
- 勝敗を先に決めて展開を合わせる処理
- AI回答を作らず直接イベントや状態を作る処理
- `parsed*`の手作業補完、解析・検証の迂回
- 失敗回答の削除
- 人間入力待ちの飛ばし、代理操作

PythonやJavaScriptは進行、保存、ハッシュ、集計、検証、回答の受け渡しに使用できます。AI文章や人間入力本文の生成には使用しないでください。

単一スレッドで実施した場合は、独立した7エージェントではなく単一AIの逐次ロールプレイであり、モデル内部コンテキストの物理隔離を証明する試験ではないことを評価書へ記載してください。

## 8. 検証とゲーム判断

各AIの`rawResponse`は、`promptText`が要求する単一JSONと必須キー・構造を満たさなければなりません。解析済みフィールドは本番パーサーの結果だけを使用し、全AIターンで次を確認してください。

```text
productionParser(rawResponse) == 保存されたparsed系フィールド
```

AI回答が失敗した場合は、本番の`responseRecoveryMode`に従います。標準設定`repair-regenerate`では、直接生成または構造草案の候補取得で、応答修復とAPI再試行が共通基準予算4回を使用し、通常生成、失敗JSONの部分修復、元契約を維持した再生成を順に実行します。多段生成では追加の必須工程分が計画予算へ加算され、校正は適用時に最大1回追加されます。状態不一致は最新プロンプトを一度再生成し、再試行可能なAPIエラーは適用される予算内で1回だけ再送します。全`rawResponse`、解析、検証、工程、使用量を保存してください。

有効候補を取得できない場合は本番`commitAiTaskFallback`を使用します。必須対象は、投票では本人の有効な投票予定、処刑候補、現行候補からのランダム選択の順で確定し、その他の対象選択では現行候補からランダム選択します。会話は`なし`、通常発言は自動フォールバック、回答優先・勝敗後感想・内部メモ整理はスキップとして記録します。API本文未取得、境界違反、代替失敗など本番が停止を要求した場合だけ終了します。自動代替は正常なAI回答としてプロンプト品質を加点しません。

人間入力にはAI用パーサーを使わず、本番の人間操作バリデーションを使用します。

ゲーム判断は次に従ってください。

- 勝者、処刑、襲撃、COを事前に決めない
- AIの判断は各AI回答、人間の判断は本人入力だけで決める
- 真占い師・真霊能者へCOを強制しない
- 標準設定では自己投票を候補へ含めず、選択された場合は本番検証で拒否する
- AIの夜行動理由は結果判明前に保存する
- 人間の投票・夜行動・襲撃先投票へ理由を追加しない
- 人狼共有発言を次のAIプロンプトまたは人間入力画面へ反映する
- GM判断は中立的に行い、操作理由を記録する

AIの発言類似、推理の浅さ、口調崩れ、不合理な判断、CO不足、人間発言への反応不足、人間の短い入力は修正せず評価へ残してください。COまたは能力結果公開が一件もなければ「未評価」とします。

## 9. 無効・中止条件

### 無効条件

次のいずれかが発生した場合は無効です。

- AIの必須JSONキー・構造欠落を解析値で補完した
- AIの`rawResponse`を通さず`parsed*`を作成した
- 本番解析・検証・状態遷移・人間操作経路を迂回した
- テンプレートで複数のAI回答を作成した
- 前ターンまたは人間入力確定前に後続回答を生成した
- 隠し情報をAI回答または人間入力画面へ混入させた
- 公開済み発言が人間入力画面または次のAIプロンプトから欠落した
- 人間入力待ち中に状態を進めた
- 人間の代わりに発言、投票、夜行動、共有、襲撃了承を生成した
- 人間入力を無断で修正・補完して登録した
- `【ストップ】`以外で中断した、または受領後に状態を更新した
- 展開を筋書きとして決めた
- 失敗回答や無効入力を削除した
- AIの`promptText`・`rawResponse`、人間の提示画面・入力本文を監査できない

無効理由と途中までの監査データを提出してください。`【ストップ】`は無効ではありませんが、「強制中断・性能評価未完了」とします。

### 中止できる条件

代替実行でも継続できない次の場合だけ中止できます。

- ZIPを読み取れない
- 完全なベースソースがない
- 本番のプロンプト生成、解析、検証、状態遷移、人間操作処理を実行できない
- ソース破損でゲームを初期化できない

ブラウザ、GUI、外部AI API、複数エージェント、ネットワーク、`npm install`、正規ビルドツールがないことだけを理由に中止してはいけません。

## 10. 終了後の監査

最低限、次を機械集計してください。

### 経路

- AIターン数・種別、人間入力待ち数・種別
- 人間の無効入力・再入力
- 必須見出し欠落、解析不一致
- 解析・検証エラー、警告、API再試行、部分修復、再生成
- AIの項目単位・行単位自動代替、GM上書き、経路迂回、代理入力

## 12. 最終回答

通常完了時は次を簡潔に記載してください。

- 有効／無効、配布アプリ試験／ソースレベル試験
- 正規ビルドとbundle整合結果
- 勝者、終了Day、人間操作キャラクター・役職
- AIターン数、人間入力待ち数、無効入力数
- AI検証エラー、解析不一致、秘密情報漏洩
- CO、能力結果、AI夜行動理由保存率、自己投票
- 最多の正規化AI発言文型割合
- 完全状態JSONの本番読込結果とZIP内同名ファイルのSHA-256一致結果
- 提出リンク、一式ZIPのSHA-256

`【ストップ】`時は、強制中断、Day・フェーズ、人間操作キャラクター・役職、AIターン数、人間入力待ち数、中断後の更新件数、性能評価未完了、提出リンク、ZIPのSHA-256を記載してください。

完走だけを成功理由にせず、AIの`promptText`と`rawResponse`、人間への提示内容と入力が本番経路を通った証拠から有効性を判定してください。
