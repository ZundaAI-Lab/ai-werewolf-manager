# チャットルーム通しテスト手順

## 1. 目的

人狼ゲームStateへ影響を与えず、チャットルームの準備、AI会話、プレイヤー発言、質問優先、個別内部メモ、参加者変更、自動保存、AIプロファイル別使用量集計までを現行仕様どおり確認する。

この手順は機能確認用であり、AI出力の内容そのものを固定しない。構造化応答、状態遷移、保存、責務境界を確認する。

---

## 2. 開始前確認

作業用コピーで次を実行し、既存回帰を先に通す。

```text
cd tools
npm ci
npm run verify
```

生成物は次の正本と一致していること。

- 本番ES Modules: `app/renderer/js/`
- チャットState: `app/renderer/js/domain/chat/`
- チャットPrompt: `app/renderer/js/prompts/chat/chatRoomPrompt.js`
- チャット保存: `app/main/chatRoomStore.js`
- Build情報: `app/renderer/generated/buildInfo.js`の`BUILD_ID`と`BUNDLE_SHA256`

チャット開始前に、人狼ゲームの現在StateをJSON出力または検査可能な形で控え、チャット操作後に人狼Stateが変化していないことを確認できるようにする。

---

## 3. 準備画面

1. サイドメニュー下部で「チャットルーム」が「外観設定」より上にあることを確認する。
2. 準備画面が上段「会話設定」、下段「参加キャラクター」の2パネルであることを確認する。
3. プレイヤー名、発言順、お題、質問優先、自動会話件数を編集できることを確認する。
4. 自動会話件数の初期値が10で、1～100の範囲に制限されることを確認する。
5. 参加キャラクターが1人1行で表示され、各行は参加選択・名前・AIプロファイル選択だけで構成され、プロフィール本文や行ごとの「AIプロファイル」見出しを表示しないことを確認する。
6. 長いキャラクター名でも名前が2行へ折り返されないことを確認する。
7. AIプロファイル欄が行全体を不必要に占有しないことを確認する。
8. 「AIプロファイル一括適用」で、選択中のチャット参加者だけが変更され、人狼側のAI割り当てが変化しないことを確認する。
9. 参加者1人以下、または参加者のAIプロファイル未設定状態では開始できないことを確認する。

---

## 4. お題と会話のきっかけ

### お題あり

1. お題を設定して2人以上で開始する。
2. 最初のAI要求のPromptを確認する。
3. `現在のお題`が渡されていることを確認する。
4. 開始用の`conversationSeeds`またはシステム汎用きっかけを同時に強制投入していないことを確認する。
5. 開始時のお題システムメッセージが会話履歴へ入ることを確認する。

### お題なし

1. 新しいチャットへ戻り、お題を空にして開始する。
2. 最初の通常発言者へ、キャラクター固有またはシステム汎用の会話きっかけが1件だけ渡ることを確認する。
3. 開始用きっかけの選択元が、キャラクター固有85%、システム汎用15%の弱い重み付けであることを回帰テストで確認する。
4. システム汎用きっかけが10種類定義されていることを確認する。
5. 最初の通常AI発言後はopening cueが消費済みになり、同じ開始用指示を継続投入しないことを確認する。

### 通常会話中

1. 2発言目以降の通常巡回では、会話きっかけなし85%、キャラクター固有10%、システム汎用5%の選択になることを回帰テストで確認する。
2. 直近6件で使用したきっかけを候補から避け、履歴を最大12件保持することを確認する。
3. 任意のきっかけがPromptへ入った場合も「自然につながる場合だけ利用し、現在の話題を打ち切らない」弱い指示であることを確認する。
4. 質問への回答専用ターンと手動優先ターンには通常会話用きっかけを入れないことを確認する。
5. 同じState・話者・AI発言番号なら、きっかけ選択が再試行ごとにランダム変化しないことを確認する。

---

## 5. 発言順と質問優先

### 固定順

1. 3人以上で`fixed`を選び、通常巡回が選択順に進むことを確認する。
2. 質問回答や手動優先が無い場合、1巡内の通常巡回では1人1回だけ発言することを確認する。

### ランダム順

1. `random`を選び、各通常巡回で参加者がシャッフルされることを確認する。
2. 通常巡回キュー自体には同じキャラクターが重複しないことを確認する。

### AIからの明示的な質問

AI応答が次のような構造を返すケースを確認する。

```json
{
  "chatMessage": "きりたんはどう思う？",
  "memory": [],
  "interaction": {
    "questionTargetIds": ["対象キャラクターID"],
    "answersMessageIds": []
  }
}
```

質問優先をONにして確認する。

1. 質問1件につき、対象キャラクターの`answer`優先ターンが1件追加されることを確認する。
2. `answer`優先ターンが通常巡回より先に生成されることを確認する。
3. `answer`優先ターンを生成しても、対象キャラクターの通常巡回枠が消費されないことを確認する。
4. 同じキャラクターへ異なる質問が2件ある場合、同じ巡回内でも回答ターンを2回生成できることを確認する。
5. 回答専用Promptには対象の`questionMessageId`の質問だけを回答対象として渡すことを確認する。
6. 回答専用応答の`answersMessageIds`に指定`questionMessageId`が無ければ応答解析を失敗させ、ターンを消費しないことを確認する。
7. 回答専用ターンで新しい質問を行うこと自体は許可するが、回答末尾へ機械的な聞き返しを要求していないことを確認する。
8. `questionTargetIds`は返答を求める明示的な質問だけを対象とし、名前の呼び掛け、同意、話題への言及だけでは登録しないようPromptが要求していることを確認する。
9. 相手への質問や別参加者への話題展開を許可する一方、毎発言の質問を強制していないことを確認する。

質問優先をOFFにして確認する。

1. AIから明示的な質問が発生しても専用回答ターンを追加しないことを確認する。
2. 質問自体は未回答質問として保持され、対象キャラクターの通常発言で自然に回答可能であることを確認する。

### 手動の「次に話す」

1. 任意キャラクターを「次に話す」で指定すると`manual`優先ターンになることを確認する。
2. `manual`優先ターンは質問回答とは異なり、対象キャラクターの未消費な通常巡回枠を移動して消費することを確認する。
3. 回答専用ターンが存在していても、明示的な手動指定を次の発言として優先できることを確認する。

---

## 6. プレイヤー発言

1. 設定したプレイヤー名で発言が履歴へ記録されることを確認する。
2. 「全員」への発言ではAI巡回順を消費・変更しないことを確認する。
3. 特定キャラクターを発言先にすると、質問優先設定に関係なく、その発言に対する`answer`専用ターンが1件追加されることを確認する。
4. プレイヤー宛て回答専用ターンを生成しても、対象キャラクターの通常巡回枠が残ることを確認する。
5. 参加者一覧の「次に話す」は質問回答ではなく`manual`優先ターンとして扱われることを確認する。
6. AI Promptの参加者一覧がAIキャラクターだけであり、プレイヤー専用プロフィールを自動生成していないことを確認する。
7. プレイヤーが一度発言した後は、直近履歴にプレイヤー名・本文・発言先がそのまま含まれることを確認する。

---

## 7. 会話履歴と個別内部メモ

1. AIへ渡す通常履歴がセッションの直近48メッセージであることを確認する。
2. 本人宛て未回答質問が通常履歴とは別枠で直近8件まで渡ることを確認する。
3. AI応答の`memory`が、そのキャラクターの`characterMemories[characterId]`へ完成版として置換保存されることを確認する。
4. 次に同じキャラクターが発言するときだけ、そのメモがPromptへ再投入されることを確認する。
5. 他キャラクターの内部メモがPromptへ混入しないことを確認する。
6. 正常な空`memory`配列で既存メモを削除できることを確認する。
7. 応答解析時に`memory`配列自体が欠落した場合は既存メモを保持することを確認する。
8. 上限が24項目、1項目200文字、総3200文字で、重複が除去されることを確認する。
9. 内部メモが通常UIへ表示されないことを確認する。

---

## 8. 会話中の参加者変更

AI生成・自動会話を停止した状態で「参加者を変更」を使用する。

1. 会話履歴、お題、プレイヤー名が保持されることを確認する。
2. 継続参加キャラクターの内部メモが保持されることを確認する。
3. 退出キャラクターの過去発言は履歴に残ることを確認する。
4. 退出キャラクターの内部メモ、そのキャラクター宛て未回答質問、そのキャラクターの回答専用ターンが削除されることを確認する。
5. AIプロファイルだけ変更した場合は現在の発言順を維持することを確認する。
6. 参加者追加・退出・並び替えを行った場合は新しい参加者構成で巡回キューを再構成することを確認する。
7. 参加・退出時のシステムメッセージが履歴へ追加されることを確認する。

---

## 9. 多人数・画面高さ

最大人数または画面に収まらない人数でチャットを開始する。

- 右側の参加者一覧だけが内部スクロールし、お題変更欄を押し出さないこと。
- 左側の会話ログだけが必要に応じてスクロールし、「次のAI発言」「自動会話」とプレイヤー発言欄を操作できること。
- デスクトップ幅でページ外側と会話ログの不要な二重スクロールが発生しないこと。

---

## 10. 自動会話

1. 「次のAI発言」で1件だけ生成することを確認する。
2. 「自動会話」で設定した`autoBatchSize`件を上限に逐次生成することを確認する。
3. 「自動会話を停止」後に新しいAPI生成を開始しないことを確認する。
4. 各AI発言の登録・内部メモ更新・保存が次の発言より前に完了していることを確認する。

---

## 11. 保存・復元・出力

1. 最新チャットが`chat-room-session.json`へ保存され、`game-autosave.json`へ混在しないことを確認する。
2. アプリ再起動後に最新チャットセッションが復元されることを確認する。
3. セッションのメッセージ上限が1200件であることを確認する。
4. 「履歴JSON出力」で現在のチャットState全体を出力できることを確認する。
5. 現行UIにチャット履歴JSON読込操作が存在しないことを確認する。
6. 「新しいチャット」で会話履歴、お題、内部メモ、未回答質問、通常巡回、優先ターン、会話きっかけ履歴が初期化されることを確認する。
7. 同操作後も参加キャラクター、AIプロファイル、プレイヤー名、発言順、質問優先、自動会話件数が引き継がれることを確認する。

---

## 12. API使用量・料金

同じAIプロファイルを人狼とチャットで使用して確認する。

1. チャット要求が通常の`desktop:generate`経路を使い、`taskType=chat-room`と対象`profileId`を持つことを確認する。
2. 人狼とチャットの使用量が用途別に分断されず、同じAIプロファイルの累計へ加算されることを確認する。
3. 料金単価を設定している場合、チャット分もそのプロファイルの推定使用額へ反映されることを確認する。
4. `profileBudgetUsd`がチャットを含む全用途累計へ適用されることを確認する。
5. プロファイル単位の使用量リセットが他プロファイルへ影響せず、詳細APIログを削除しないことを確認する。

---

## 13. 人狼State非干渉

チャット開始前に控えた人狼Stateと比較し、チャット準備、会話、参加者変更、新しいチャット、履歴出力を行っても、人狼の役職、陣営、Day、投票、CO、能力、ゲームrevision、Undo／Redoが変更されていないことを確認する。

チャットPromptにも人狼の役職・陣営・投票・能力・疑い・勝敗、`discussionBehavior`、`reasoningProfile`を投入しないことを確認する。

---

## 14. 合格条件

- `npm run verify`が成功する。
- 上記のチャット機能契約を満たす。
- チャット操作が人狼Stateへ影響しない。
- AIプロファイル別使用量へチャット分が正しく加算される。
- 保存・参加者変更・内部メモ・質問優先で会話ログが意図せず消失しない。
- 多人数でも主要操作が画面外へ押し出されない。
