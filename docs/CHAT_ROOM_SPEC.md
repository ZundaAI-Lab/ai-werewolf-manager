# 自由会話チャットルーム現行仕様

この文書は、人狼ゲームとは独立した「自由会話」チャットルームの現行実装仕様をまとめる。人狼観戦チャットは`docs/SPECTATOR_ROOM_SPEC.md`を正本とし、本書へ観戦固有の状態・再生規則を混在させない。実装の責務境界は`docs/AI_WORK_RULES.md`にも従う。

## 1. 目的と独立性

チャットルームは、登録済みキャラクターデータとAIプロファイルを利用し、複数のAIキャラクターとプレイヤーが自由会話を行う機能である。人狼ゲームの役職、陣営、Day、投票、CO、能力、疑い、勝敗は扱わない。

チャットルームは次の人狼用状態へ混在させない。

- ゲームState
- `discussionRuntime`
- ゲームrevision
- Undo／Redo
- 人狼の内部メモ、判断状態、陣営戦略

主な正本は次のとおり。

```text
app/renderer/js/domain/chat/chatRoomState.js       セッション状態、通常巡回、優先ターン、参加者差し替え
app/renderer/js/domain/chat/chatRoomMemory.js      キャラクター個別内部メモの上限・正規化
app/renderer/js/prompts/chat/chatRoomPrompt.js     チャット専用Promptと応答解析
app/renderer/js/prompts/chat/chatRoomConversationCuePolicy.js  会話きっかけ候補・重み・重複抑制
app/renderer/js/ui/controllers/chatRoomController.js  UI・AI生成・保存の調停
app/renderer/js/ui/views/chat/chatRoomView.js      準備・参加者編集・会話画面
app/main/chatRoomStore.js                          独立自動保存
```

## 2. 画面位置と準備画面

サイドメニュー下部の「外観設定」の直前に「チャットルーム」を配置する。

準備画面は上下2パネル構成とする。

1. 上段: 会話設定
2. 下段: 参加キャラクター

会話設定は次を保持する。

| 項目 | 現行仕様 |
|---|---|
| プレイヤー名 | 最大80文字。空欄は「プレイヤー」 |
| 発言順 | `random`=巡回ごとにランダム / `fixed`=選択順 |
| お題 | 任意。準備・変更画面の入力欄は最大240文字 |
| 自動会話の一区切り | 1～100発言、初期値10 |
| 質問優先 | 初期値ON |

参加キャラクターは2人以上必要で、キャラクター管理で有効なキャラクターだけを使用する。各参加者へ有効なAIプロファイルを1つ割り当てる。参加者一覧は1人1行で、プロフィール本文は表示せず、参加選択・キャラクター名・AIプロファイル選択だけを表示する。

「AIプロファイル一括適用」は、現在チャットへ選択している参加キャラクターだけを対象にする。人狼側のAI割り当て`assignments`は変更しない。

## 3. 会話開始とお題／会話のきっかけ

チャット開始時は、会話履歴、未回答質問、キャラクター個別内部メモ、通常巡回、優先ターン、会話きっかけ履歴を新しいセッション会話として初期化する。

### 初回発言とお題

お題が1文字でも設定されている場合、初回用の`opening.seed`は選択せず、保存せず、最初のPromptへ渡さない。最初のAIは設定されたお題からキャラクターらしい自然な一言で会話を始める。開始時にはお題を示すシステムメッセージを履歴へ追加する。

お題が空の場合は、最初の通常発言者へ初回用の会話きっかけを1件だけ選ぶ。候補は次の2系統で、選択元の重みはキャラクター固有85%、システム汎用15%とする。選択元に候補がない場合はもう一方へフォールバックする。

- キャラクター固有: `character.conversationSeeds`
- システム汎用: 本機能が持つ10種類の汎用cue

初回きっかけは話題名を読み上げるのではなく自然な台詞へ変換させる。最初の通常発言が登録された時点で`opening.seed`は消費済みとなる。質問への専用回答ターンが先に発生しても`opening.seed`は消費せず、回答Promptへも渡さない。

### 通常会話中の弱い会話きっかけ

最初のAI発言以後、**通常巡回ターンに限って**低確率で任意の会話きっかけを提示する。選択重みは次のとおり。

| 選択 | 重み |
|---|---:|
| きっかけなし | 85% |
| キャラクター固有`conversationSeeds` | 10% |
| システム汎用cue | 5% |

このcueは命令ではなく「現在の流れから自然につながる場合だけ使ってよい着想」としてPromptへ渡す。現在の話題を打ち切って切り替えること、cueを必ず使うこと、cueから必ず質問することは要求しない。質問専用回答ターンと手動指定ターンには通常会話cueを渡さない。

直近6件で利用したcue IDは候補から優先的に外し、候補を使い切った場合だけ再利用する。Stateには直近12件までの`conversationCueHistory`を保持する。選択はセッションID・話者ID・AI発言数・巡回数から決定的に行い、同じ状態の再生成でcueがランダムに変化しないようにする。

システム汎用cueは次の10系統を正本とする。

1. 最近ちょっと気になったことや小さな発見
2. 食べ物や飲み物、好き嫌い
3. 趣味や遊び、暇なときの過ごし方
4. 季節や天気、その時期ならではのこと
5. 行ってみたい場所や旅行
6. 昔の思い出や子供の頃の話
7. 最近の小さな失敗や意外だった出来事
8. 日常のこだわりや習慣
9. 「もし○○だったら」という軽い仮定
10. 最近おすすめしたいものや人に勧められたもの

## 4. 発言順

発言順は「通常巡回」と「優先ターン」を分離して扱う。通常巡回は全員参加を保証するための枠であり、質問への回答は通常巡回枠を消費しない。

### 通常巡回

固定巡回では選択された参加者順で巡回する。ランダム巡回では各巡回の開始時に参加者をシャッフルする。通常巡回だけを数えた場合、1巡内では原則として1人1回発言し、可能な場合は前巡最後の発言者が次巡の先頭へ連続しないよう入れ替える。

### AIからの明示的な質問

AIが**相手から返答を求める明示的な質問**を実際に行った相手だけを`questionTargetIds`へ返す。名前を呼んだだけ、同意しただけ、話題に出しただけ、返答を求めない呼び掛けは質問先にしない。質問そのものは任意であり、毎回質問することを要求しない。

質問優先がONの場合、質問メッセージと質問先の組み合わせごとに`priorityTurns`へ`kind: "answer"`の専用回答ターンを1件追加する。

```json
{
  "kind": "answer",
  "speakerId": "質問されたキャラクターID",
  "questionMessageId": "元質問メッセージID"
}
```

回答ターンは通常巡回キューから対象キャラクターを削除しない。したがって同じ巡内で同じキャラクターが「質問Aへの回答」「質問Bへの回答」「本人の通常巡回」のように複数回発言できる。複数質問があれば質問1件ごとにAI生成を行う。

質問優先がOFFの場合、AI質問は`unresolvedQuestions`へ保持するが専用回答ターンは追加しない。対象キャラクターの通常巡回などで自然に回答した場合に解消できる。

専用回答ターンでは元質問1件だけを今回の必須回答としてPromptへ渡す。AI応答はその`questionMessageId`を`answersMessageIds`へ必ず含めなければならず、欠落した応答は解析失敗として再生成対象とする。回答済みになった質問に対応する未消費回答ターンは除去する。

### 手動の「次に話す」

参加者一覧の「次に話す」は質問回答とは別の`kind: "manual"`優先ターンである。対象が通常巡回キューに残っている場合はその通常枠を優先ターンへ移動し、同じ通常巡回枠を二重には残さない。手動指定は待機中の質問回答ターンより先に置く。

優先ターンの消費後は残っている回答ターンを処理し、それから通常巡回へ戻る。

## 5. プレイヤー発言

プレイヤーはAI巡回とは独立していつでも発言できる。設定したプレイヤー名を`speakerName`として履歴へ保存する。

- 発言先「全員」: 履歴へ追加するだけで通常巡回キューと優先ターンを変更しない
- 特定キャラクター: 対象への未回答質問として登録し、**質問優先設定に関係なく**質問1件ごとの専用回答ターンを追加する

プレイヤーの特定キャラ指定も対象の通常巡回枠を消費しないため、同一巡内で追加回答と通常発言の両方が発生できる。

現行仕様ではプレイヤー専用プロフィール、口調、キャラクターカードは存在しない。またAI Promptの「参加者」一覧はAIキャラクターだけで構成し、プレイヤーを独立参加者として常時列挙しない。AIがプレイヤーについて参照する情報は、会話履歴に現れたプレイヤー名、発言内容、発言先を正本とする。

## 6. AIへ渡すキャラクター情報

発言者本人について次を渡す。

- 名前
- プロフィール
- 一人称
- 一般的な二人称
- 話し方
- 語尾傾向
- 避ける表現
- 発言量
- 発話例
- 他の現在参加AIキャラクターへの相手別呼称

人狼専用の`discussionBehavior`、`reasoningProfile`、役職・陣営・投票・能力・疑い・勝敗情報はチャットPromptへ渡さない。

## 7. 会話履歴と未回答質問

AI生成時の通常会話履歴は、セッションに保存されたメッセージのうち**直近48件**を全文で渡す。AI発言、プレイヤー発言、システムメッセージを同じ時系列に含める。

各行は概ね次の情報を持つ。

```text
#連番 [メッセージID] 発言者名 → 発言先: 本文
```

発言先がない場合は矢印部分を省略する。

発言者本人宛ての未回答質問は通常履歴とは別枠で直近8件まで渡す。専用回答ターンでは、そのターンが指す元質問1件だけを今回の未回答質問として渡す。

セッション自体に保持するメッセージは最大1200件で、上限超過時は古いメッセージから削除する。

## 8. キャラクター個別内部メモ

長期会話で48件より前の重要情報を維持できるよう、キャラクターごとに非公開の個別内部メモを持つ。共有メモは作らない。

AIは各発言で`memory`へ「今回の発言後に維持すべき内部メモの完成版」を返す。差分追記ではなく、返された完成版で本人の既存メモを置換する。AIには不要情報の削除、訂正情報の更新、推測を事実として残さないことを指示する。

現行上限は次のとおり。

| 上限 | 値 |
|---|---:|
| 項目数 | 24 |
| 1項目 | 200文字 |
| 合計 | 3200文字 |

同一内容の重複は除去する。メモは発言者本人にだけ次回再投入し、他キャラクターへ渡さない。UIにも表示しない。

応答解析で`memory`配列を取得できない場合は、既存メモを消さず保持する。正常な空配列が返された場合は「保持すべきメモなし」として既存メモを削除できる。

## 9. チャット専用Promptと応答契約

Prompt Envelopeは通常のProvider通信基盤へ渡すが、内容はチャット専用とする。主な区画は次のとおり。

```text
commonGameContext      人狼ではないこと、AI参加者、お題
taskInvariantContext   会話ルール、弱い質問/話題展開誘導、質問判定、内部メモ更新ルール
stablePlayerContext    発言者本人のキャラクター設定・相手別呼称
taskVariableContext    今回の話者
dynamicTaskPrompt      本人の内部メモ、直近48件、今回対象の未回答質問、回答ターン/任意cueを含む発言指示
```

構造化応答は次を使用する。

```json
{
  "chatMessage": "画面へ表示する本人の台詞",
  "memory": ["今後も維持する本人だけの内部メモ"],
  "interaction": {
    "questionTargetIds": ["返答を求める明示的な質問をした現在参加中の他キャラクターID"],
    "answersMessageIds": ["今回実際に回答した本人宛て未回答メッセージID"]
  }
}
```

`questionTargetIds`は現在参加中の他キャラクターだけへ絞り、`answersMessageIds`は本人宛て未回答メッセージIDだけへ絞る。質問専用回答ターンでは指定された元質問IDが`answersMessageIds`に含まれることを追加検証する。

通常Promptでは、相手の発言に興味があれば短く尋ねたり別参加者の意見を聞いたり、自分の経験・好み・別視点・少し違う話題へ自然に広げてもよいと伝える。ただし毎回質問する必要はないこと、回答末尾へ機械的に聞き返しを付けないことも同時に明記し、質問を強制しない。

JSON解析に失敗した場合は、同じチャット発言について最大1回の再生成を行う。最終的に解析できない場合は発言登録せず、ターンを消費しないため同じ通常巡回・回答・手動優先ターンが次の候補として残る。

## 10. 会話中の参加者変更

AI生成中・自動会話中でない場合、「参加者を変更」から現在のチャットを維持したまま参加キャラクターとAIプロファイルを編集できる。適用には2人以上かつ全員の有効AIプロファイル設定が必要である。

適用時の扱いは次のとおり。

- 会話履歴: 保持
- お題: 保持
- プレイヤー名: 保持
- 継続参加キャラクターの内部メモ: 保持
- 退出キャラクターの過去発言: 保持
- 退出キャラクターの内部メモ: 削除
- 退出キャラクター宛て未回答質問: 削除
- 退出キャラクターに関係する優先ターン: 削除
- 継続参加者宛ての未解決質問回答ターン: 保持
- AIプロファイルだけ変更: 現在の通常巡回・優先ターンを維持
- 参加者追加・退出・並び替え: 新しい参加者構成で通常巡回キューを再構成し、有効な質問回答ターンだけ保持

参加・退出がある場合はシステムメッセージを履歴へ追加する。

## 11. お題変更

会話中にお題を変更または解除できる。変更時はシステムメッセージを履歴へ追加し、次回以降のPromptへ新しいお題を渡す。

開始後にお題を解除しても初回用`opening.seed`を新たに作り直さない。通常巡回で低確率に選ばれる任意cueは初回seedとは別契約であり、お題の有無にかかわらず現在の流れへ自然につながる場合だけ利用できる。

## 12. 自動会話と停止

「次のAI発言」は1件だけ生成する。「自動会話」は`autoBatchSize`件を上限として逐次生成し、各発言の状態保存後に次の発言へ進む。初期値は10件。

「自動会話を停止」は新しい生成を開始せず、実行中要求がある場合はキャンセルを試みる。

## 13. 保存・履歴出力・新しいチャット

最新セッションはElectron Mainの`chat-room-session.json`へ独立自動保存する。schemaVersionは共通`dataCompatibility`を正本とし、製品版1.0.0の基準は1、保存サイズ上限は8MiB。対応Migrationがある旧schemaだけを現行schemaへ変換してから復元し、Migrationのない旧schema・未来schema・無版schemaは推測して復元しない。

「履歴JSON出力」は現在のチャットState全体を`chat-room-<sessionId>.json`として出力する。現行UIにはこの履歴JSONを読み込む機能はない。

「新しいチャット」は次を初期化する。

- 会話履歴
- お題
- キャラクター個別内部メモ
- 未回答質問
- 通常巡回・優先ターン
- 会話きっかけ履歴

次は引き継ぐ。

- 参加キャラクター
- 参加キャラクターごとのAIプロファイル
- プレイヤー名
- 発言順モード
- 質問優先
- 自動会話の一区切り

## 14. API使用量・料金

チャットAI生成は既存の`desktop:generate`を使用し、`taskType`は`chat-room`、`profileId`は各チャット参加者に割り当てたAIプロファイルIDとする。

料金管理の正本はチャットセッションIDではなく**AIプロファイルID**である。同じAIプロファイルを人狼、チャットルーム、事後分析、生成工程テスト、接続テストなどで使用した場合、そのプロファイルの累計へ加算する。

AIプロファイルの料金設定は次を持つ。

- 通常入力 USD / 100万tokens
- キャッシュ入力 USD / 100万tokens
- キャッシュ書込 USD / 100万tokens
- 出力 USD / 100万tokens
- プロファイル利用上限 USD

単価は自動判定しない。設定済み単価をAPI要求時点のusageへ適用し、過去の使用額へ遡及しない。利用上限0は無制限。上限ありの場合は現在のプロファイル累計と次回要求の最大出力までを保守的に見積もり、超過見込みならAPI送信前に停止する。

使用量リセットはプロファイル単位または全プロファイル一括で行い、詳細APIログは削除しない。

## 15. AIプロファイルJSON転送との関係

チャットルームはAI管理に登録済みのAIプロファイルを参照する。AIプロファイルJSON転送も共通`dataCompatibility`の対象とし、製品版1.0.0の基準`schemaVersion`は1とする。チャット参加者の`profileId`はチャットセッション側に保持し、人狼参加者の`assignments`とは別管理とする。

転送JSONへ含めるのはプロファイル設定と生成工程依存であり、次は含めない。

- APIキー
- API使用量・料金履歴
- 人狼参加者への割り当て
- チャット参加者への割り当て

読込時はプロファイルIDを新規採番し、同梱された生成工程依存プロファイルの参照も新IDへ付け替える。
